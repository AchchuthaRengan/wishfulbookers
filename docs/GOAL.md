# Navlands Goal

Status: Approved direction  
Version: 0.3.0  
Date: 2026-07-11

## Product outcome

Help an employee see a believable route from their present role to a chosen
role without needing to understand career taxonomies, ranking formulas, or AI
prompting.

The MVP succeeds when an unknown user can onboard, recognize themselves in the
starting map, understand the next major roles and decisions, compare existing
and AI possibilities, and save or fork a path they would genuinely use.

## Launch focus

- Employee persona.
- English interface.
- Global availability with best-effort country data.
- Launch-quality density for support → software roles in product companies and
  QA → development.
- 50–100 roles, 200–400 transition components, and 20–30 Curated ladders.

## Product character

Navlands should feel like exploring a map, not completing a career assessment.

It should be:

- visually understandable;
- friendly and progressive;
- honest about origin and uncertainty;
- useful before asking for contribution;
- playful enough to invite exploration;
- strict enough internally to remain trustworthy.

## Primary value loop

```text
onboard -> see path -> reveal possibilities -> compare -> fork/refine/save
        -> optionally publish Lived path -> improve supply for the next user
```

## MVP validation goal

Before broad promotion:

- 90% of fixed launch-corridor fixtures return one usable source-grounded path;
- 70% return a top result satisfying the constraint thresholds associated with
  the fixture's two ordered priorities;
- users can explain the next role and the main constraint mismatch after using
  the result;
- invalid AI output costs the user nothing;
- no content type is mistaken for verification or guaranteed success.

## Non-goals

- career outcome prediction;
- proof collection;
- résumé replacement;
- job marketplace;
- social feed;
- celebrity simulation;
- progress tracking;
- employer, parent, or student workflows;
- maximizing daily screen time through artificial engagement.

Retention must come from saved exploration, new Lived supply, useful updates,
fork activity, and repeated career questions—not manipulative addiction.

## Delivery rule

There are no founder-imposed calendar deadlines in the development plan.
Progress is milestone-based: a milestone completes only when its requirements,
tests, security checks, and documentation evidence pass.
